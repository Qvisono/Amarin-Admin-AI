# Заметки Codex по Amarin Admin AI

Дата знакомства: 6 ноября 2026. Источники: весь прежний `CLAUDE.md`, README, проекты решения, workflow CI и выборочная проверка ключевых исходников. Это краткая карта для продолжения работы; подробные причины и история решений перенесены в `docs/agent-guide/`.

## Как восстановить контекст

Корневой `AGENTS.md` направляет новую сессию к этим заметкам. Codex читает такие файлы перед работой с проектом; механизм описан в [официальной документации OpenAI](https://learn.chatgpt.com/docs/agent-configuration/agents-md). Настройки Codex вне репозитория для этой памятки не менялись.

Сначала проверь рабочее дерево, версию приложения и актуальную реализацию нужной функции. Затем прочитай соответствующие пункты `docs/agent-guide/` по указателю в `CLAUDE.md`: это накопленная история, где поздний раздел иногда уточняет ранний. Снимок ниже описывает состояние на дату знакомства, а не обещание неизменности проекта.

## Назначение и состав решения

Amarin Admin AI - переносимое Windows-приложение: локальные переписки с моделями Venice, OpenRouter, прямых провайдеров и совместимых серверов; агенты, системные инструменты, документы, голос, расписания, управление компьютером и браузером. Ключи пользователя оплачивают запросы. Роза - отдельный персонаж со своим состоянием и моделью, без доступа к системным инструментам приложения.

## Границы архитектуры

- Направление зависимостей: окно -> логика -> хранилища/сеть. `ArchitectureTests` запрещает Core ссылки на WPF и приложение, а нижним четырём папкам - знание движков.
- `ProfileScope` держит данные выбранного профиля; `AppServices` пересылает их окну. Смена профиля через `UseProfile` должна переключать хранилища и все настройки, а не только видимые контролы.
- Процессные настройки инструментов ставит `AppComposition.ApplyProcessWide`. Сохраняй существующие статические точки: их перевод в другой механизм затрагивает замороженные зоны.
- Большие классы разделены по обязанностям: `ChatEngine.*`, `VeniceClient.*`, `ChatStore.*`, `MainWindow.*`. Новый функционал не складывается в основной файл без разбора.
- Запуск до первого кадра минимален. Настройки создаются лениво после кадра; состояние хранит `AppSettings`. `StartupJit`, `WindowFirstPaint`, прогрев обоев и первая порция списка чатов имеют намеренный порядок.

## Ходы, провайдеры и запросы

- `TurnRegistry` допускает до трёх параллельных ходов, по одному на чат. `SendPlanner` проверяет возможность отправки до очистки поля и вложений. При открытии чата сначала нужна живая сессия из реестра.
- Модель, размышление, ключ, стоимость и cache key принадлежат ходу (`VeniceTurnContext`). Ambient scopes передаются по цепочке; фоновые независимые задачи не должны случайно наследовать чужой ход.
- Один ход может дать несколько ответов на сообщения из очереди. `VeniceTurnContext.Total` копит весь ход, `MessageTotal` - только текущий ответ; `BeginNextMessage` сбрасывает счёт ответа, его маршрутизатор и добавленное время. `FinishAssistant`/`Settle` используют счёт ответа, включая токены без цены; продолжение отменённого ответа восстанавливает лишь его расходы через `RecoverTurnTotal`.
- `ModelRef` отделяет провайдера от model ID по первому двоеточию; на провод идёт `Bare`. Старые Venice ID остаются без приставки ради совместимости. Не определяй провайдера по выбранной строке ключа на странице трат.
- `ProviderSpec` описывает протокол и возможности. `ModelSlots.All`, `Binding`/`WriteBinding`, `CredentialFor` - единые точки слотов и назначения ключей. Назначенный слоту ключ должен принадлежать тому же провайдеру.
- URL, авторизация и политика организации применяются к конкретному `HttpRequestMessage` через `VeniceClient.Request`. Нельзя менять `DefaultRequestHeaders`/`BaseAddress` общего клиента для очередного запроса.
- Anthropic использует `AnthropicMessages`/`AnthropicStream`, а не общий OpenAI JSON. `ReplayBlocks` нужны для корректного продолжения размышления и инструментов: не сериализуются на диск, но сохраняются при внутренних копиях.
- Выбранную человеком модель не заменяют из-за перегрузки. Каталог, который не загрузился, не является основанием лечить назначения слотов.
- Аргументы модели разбирает `ToolArguments.Parse`. `AgentOptions` копируется через `with`, чтобы не терять делегаты расходов, балансов и ограничений. Возвращённую сервером цену получают через `ReportedCost()`, оценки прямых провайдеров - через ценовой каталог; расход записывается до проверки достигнутого лимита.
- Промпты задают общие правила и форматы, а не набор разобранных пользовательских случаев. При изменении базового промпта прежнее умолчание добавляется в `LegacyAgentPrompts`; обязательные динамические правила должны доходить и до пользовательских сохранённых промптов.
- Пакетные модели OpenRouter `:batch` идут через `RunBatchAsync`/`OpenRouterBatchPlan`; служебные запросы используют обычного близнеца. Особенности очереди и отмены читать в подробной памятке.
- `AgentMemoryBook` и `AppSettings.AgentMemory` определяют срок памяти общения с агентом. Старое утверждение, что разговор существует только внутри хода, уже неполно.
- Пересадка работающего агента продолжает снимок текущей попытки через `Agent.ResumeAsync`, без повторного добавления сообщения чата. Сохраняются результаты инструментов, прочитанные уточнения человека для SynGuard и cache key; подписи размышления переносятся только на ту же модель. Подробности и отмена посреди раунда - в `docs/agent-guide/10-browser-agent-chat.md`, пункт «Пересадка работающего агента сохраняет найденное».

## Интерфейс: места, где легко сломать поведение

- Три источника UI-строк должны совпадать: `Strings.ru.xaml`, `Strings.en.xaml`, `StringsRu.cs`. Словарь локализации - слот 4 `MergedDictionaries`, слот 3 занят оформлением. Перенос строки в XAML: `&#10;` и `xml:space="preserve"`.
- Фоновое обновление настроек обращается только к уже созданным страницам через `BuiltPage<T>()`; обычное свойство страницы может нечаянно построить её. Для вопросов/замечаний используются `ShowNoticeAsync` и единая точка `Notify`, с предусмотренными исключениями для напоминаний.
- `ChatTitle.Default` и другие дисковые маркеры переводятся при показе, не меняются на переведённые значения в хранилище. Новые enum/темы сериализуются с учётом отката на старый exe.
- Цвета берутся из тем через ресурсы. Попапы регистрируются в `PopupManager`; общий вид задают стили `Resources.xaml`. У модальных карточек раскладка `Grid`, а не бесконечно растущий вертикальный `StackPanel`.
- Логотип модели разрешает встроенный `Providers/ModelLogoCatalog.json`: точный ID, семейство своего автора, затем автор. У неизвестного автора остаётся буква. Источники графики, SHA256, импорт SVG в WPF и снимок каталога находятся в `tools/model-logos/`; изображения загружаются только оснасткой сопровождения, интерфейс работает с локальными ресурсами. Обе темы проверяются `ModelLogoRenderingTests`.
- Цена одного сообщения обновляется через `RefreshMessageView`; изменения текущей ленты - через `ReconcileTranscript`, повторная отрисовка без сброса лупы - `RebuildTranscript(resetZoom: false)`. `RenderSession` предназначен для открытия другого чата.
- Ширина/перераскладка ленты меняется через существующие `BeginTranscriptReflow`/`EndTranscriptReflow` или `ReflowTranscriptOnce`. Список чатов сверяется через patch и сохранённый слепок, не перестраивается целиком.
- Оверлей блокирует чат прозрачным `ChatShield`; изменение наследуемых `IsEnabled`/`IsHitTestVisible` большого дерева даёт побочные эффекты и дорогую работу.
- Масштаб `UiScale` реализован как синтетический DPI. Геометрию maximized-окна исправляет только `WindowMaximizeFix`; не добавлять конкурирующие перехватчики `WM_GETMINMAXINFO`.
- Горячие клавиши разбираются до `ShouldKeepKeyboardFocus`; назначения берутся из `HotkeyMap.Effective`. Новая клавиша не должна перехватывать обычный набор текста.

## Хранение, инструменты и безопасность приложения

- Корень данных: `%APPDATA%\Amarin Admin AI`. Старый профиль по умолчанию остаётся в корне; другие - `profiles/<id>`. Не менять раскладку так, чтобы потерялись старые чаты.
- Запись чатов и вложений организована на границе `ChatStore`; в памяти API-вложения остаются base64. Черновики принадлежат каждому чату. `SaveDeferred` применяется к непрерывным изменениям, а не к каждому сохранению.
- Новый тип данных регистрируется в экспорте/импорте, подсчёте места и удалении. Для исключений есть `DataBundleCoverageTests`; нельзя считать, что произвольный новый JSON автоматически попадёт в архив.
- Секреты защищаются DPAPI и `SecretRegistry`/`SensitivePaths`. Legacy Venice/OpenRouter ключи - `keys.json`, ключи новых провайдеров - `provider-keys.json` ради чтения старыми версиями. Ключи окружения не копируются на диск.
- Все пути выполнения инструментов, включая чат и рецепты, проходят общий шлюз. Режим подтверждений, чтение/запись, SynGuard и организационные политики остаются на существующих уровнях. Исключения для computer/browser не расширяются на другие инструменты.
- `ConfirmationQueue`: отмена через `CancelForSession`, ответ через конкретный request, а не текущую голову очереди. Нельзя отменять вопросы соседних чатов.
- Чтение/правка документов и файлов разделяются: `FileToolState` хранит знание файла, штампы и блокировки; существующий документ нельзя править по старому непрочитанному состоянию. Книгой созданных документов управляет `AiDocuments`.
- `ContextHygiene` меняет только отправляемую копию истории, сохраняет пары вызов/результат, последние два хода человека и данные на диске. Новые правила очистки должны оставаться детерминированными и учитывать границу кэша.
- Временный чат не сохраняется через `ChatStore`; это не означает отсутствия записей аудита и расходов. У него также отдельные ограничения на черновики, deferred и связь с Розой.
- Аудит дописывается и проверяет цепочку; импорт не должен переписывать существующий журнал. Сетевой текст никогда не становится разрешением на системное действие.

## Computer, браузер, документы, голос и Роза

- `IComputer`/`IComputerStage`, `ComputerSafety`, `ComputerSession` находятся в Core; Windows-адаптер выполняет команды. Один сеанс сопровождает весь прогон, сохраняет масштаб/координаты и освобождается в конце.
- `computer` и `browser` не распараллеливаются. Цели/id действуют только по последнему чтению; координаты физические, без `UiScale`. Доступ к компьютеру учитывает настройки, организационные политики, наличие сцены и локальную цель.
- Браузер агента работает через DOM в отдельном WebView2-окне и профиле, не забирает cookies обычного браузера пользователя. Порты `IWebBrowser`/`BrowserHub` находятся в Core, фабрику окна устанавливает приложение.
- В обычном режиме явно порученная работа мышью/браузером имеет предусмотренное шлюзом поведение без повторного вопроса на каждый шаг; `ComputerSafety`, read-only, SynGuard и политики при этом продолжают действовать. Не переносить упрощение на весь шлюз инструментов.
- История снимков и страниц сокращается по существующим правилам `ComputerHistory`, сохраняя полезную память и стабильное начало запросов. Результат инструмента привязан к своему вызову, включая пересадку агента.
- PowerPoint сейчас читается, создаётся и редактируется: `SlidesReader`, `SlidesWriter`, `SlidesEditor`, `SlidesTemplate`. Word/Excel/PDF используют свои reader/writer/editor. Порядок OpenXml и форматирование ячеек важны.
- `TableQuery` считает анализ таблиц программно. Диаграмма в переписке - блок `chart`, а не картинка. Для документов нужны конкретные схемы инструментов, не свободный JSON.
- OCR и извлечение медиа через WinRT выполняются скриптами PowerShell 5.1 (`WinRtScript`). Русское распознавание речи в режиме «Авто» идёт в облако; отдельный голосовой разговорный режим удалён по решению пользователя, не возвращать его попутно.
- `MicRecorder` собирает завершённые буферы в порядке очереди драйвера, сохраняя позицию между опросами и при остановке. Обход массива с нуля перемешивает звук при переходе через конец кольца; проверяет `MicRecorderTests`. Таймер опроса идёт с приоритетом `Normal`: фоновый уступал очередь анимации точек громкости и отставал от кусков по 100 мс.
- `ProjectFox` грузится лениво через переходник `FoxWindowHost`/`IFoxHooks`; до прихода Розы сборка не должна задерживать первый кадр. Единственное создание выполняется через `CreateFox` с `NoInlining`. Brain/Mind/Storage обходятся без WPF, отрисовка - в View.
- Разум Розы работает отдельно под `ExecutionContext.SuppressFlow`, со своим слотом модели. У него нет инструментов приложения и доступа к вложениям/ответам ассистента. Эмоции, дружба, воля и допустимые действия решаются таблицами и Brain, а не произвольной командой модели.
- Состояние Розы и дневник принадлежат профилю (`fox/state.json`, `fox/diary.json`) и учитывают шифрование. Изменение дружбы проходит через `FoxFriendship.Change`. Спрайты - встроенные `Sprites/*.fox`, рисунок проверяют `FoxSpriteTests`.

## Проверки и выпуск

Основные команды находятся в `AGENTS.md` и начале `CLAUDE.md`. Обычный CI собирает Release с `-warnaserror` и запускает тесты с `Category!=Wpf`. Ручной workflow `Tests` включает оконные проверки, но особенности экрана/STA на раннере требуют сверки с настоящей Windows. Английская культура, ANSI 1252 и UTC на CI не совпадают с русской рабочей машиной; зависимость от культуры/часового пояса тест задаёт явно.

WPF-фикстура - `Amarin.AdminAI.Tests/WpfFixture.cs`; граф без системных побочных эффектов - `UiServices.cs`. UI-объекты читаются и меняются только внутри вызова общего UI-потока. Изменивший процессную статику тест возвращает её и изолируется коллекцией.

| Проверка | Точка входа / условие |
|---|---|
| Архитектура и композиция | `ArchitectureTests`, `AppCompositionTests` |
| Строки и типографика | `LocalizationTests`, `LocalizationKeyUsageTests`, `SourceLiteralTests`, `TypographyTests` |
| Категория WPF-тестов | `TestCategoryTests`, образец collection + trait в `UiShotTests` |
| Снимки интерфейса | `UiShotTests`, `AMARIN_UI_SHOTS=<папка>`, дополнительно `AMARIN_UI_SHOTS_ONLY`, `_ALL`, `_THEMES`, `_MIN` |
| Производительность UI / запуска | `PerfBenchTests`: `AMARIN_PERF_BENCH`; `StartupBenchTests`: `AMARIN_STARTUP_BENCH`; `PerfLog`: `AMARIN_PERF_LOG=1` |
| Горячие пути Core | `dotnet run -c Release --project Amarin.AdminAI.Benchmarks -- --filter '*'`; сравнивать на одной машине |

Наличие live-теста в общем зелёном прогоне не доказывает, что он проверил настоящий сервер: без opt-in такие тесты сразу возвращаются. Не включай их вместе с обычной проверкой заметок.

Версия приложения живёт в `Amarin Admin AI/Amarin Admin AI.csproj` и дизайнерской подписи `SettingsVersionText`; Core/Fox наследуют её. Runtime-версия берётся из informational version с semver, а не только чисел AssemblyVersion. До сборки нужен файл release notes для встроенного ресурса.

Публикация из PowerShell одной строкой (выполнять при задаче на сборку релиза, подставив версию):

```powershell
dotnet publish "Amarin Admin AI/Amarin Admin AI.csproj" -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:EnableCompressionInSingleFile=true -p:DebugType=none -o "release/publish-<версия>"
```

Нужны оба списка исключений ReadyToRun, native self-extract и compression. Выход - один exe и `appsettings.json`; релизный exe сопровождается `SHA256SUMS`. Обновление сверяет сумму и применимые проверки подписи; автомат `UpdateMachine` остаётся чистым, внешнюю работу выполняют порты. Выпущенный exe не подменяют исправлением без новой версии. `release.yml` запускается push с изменением release notes в `main`, prerelease определяется пометкой версии.

Специальные режимы CLI обрабатываются с учётом single-instance mutex: smoke/update/rollback/await-exit идут до захвата; `--prompt` лишь заполняет поле, отправка требует `--send`. Закрытое окно может оставлять фоновое завершение обновления с удержанием mutex; этот жизненный цикл нельзя упрощать до немедленного выхода.
