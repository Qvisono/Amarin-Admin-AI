# 03. Все настройки и вкладки: исходник → телефон

Источник состава — `UI/Settings/SettingsView.xaml.cs`: 11 страниц. На телефоне остаётся 10, раздел «Автоматизация» исключён. Группы исходника сохраняются: «Основное», «Модель», «Защита и данные». Полная фактическая опись разметки с названиями контролов — `inventory/settings-source.md`. Здесь для каждой группы задана мобильная судьба; значения в скриншотах одного профиля не считать заводскими настройками.

Общие правила: все подписи русские с ресурсами для локализации; переключатели меняются сразу, редакторы сохраняются явно. Любой новый мобильный параметр ниже обозначен как адаптация. В первом этапе всё работает на локальных demo-данных; сетевые и защищённые операции имеют fake-реализацию и честное состояние, а не кнопки с пустыми обработчиками.

## 2. Оформление — NavIcon.Appearance, розовый

Главная страница: «Тема» → каталог; «Фон и акцент» → редактор; «Интерфейс» → шрифт/размер/доступность; анимации; сброс оформления. Каждый подпункт имеет live preview мини-чата, а не перекрашивает случайную часть экрана.

Темы: сохранить **все 53** `Palette.*.xaml`, их имена и связанный `ThemeCatalog`. Карточки сеткой, 2 в ряд при достаточной ширине, 1 при увеличенном тексте; название + три цветовых образца + selected. «Следовать системе» и «Высокая контрастность» сохраняются. Для системной темы разрешить выбор пары светлая/тёмная (мобильная адаптация), стартовая пара Light/Dark. Значения оттенков не извлекать пипеткой из затемнённого скриншота — брать ресурсы.

## 3. Профиль — NavIcon.Profile, синий

Верхняя карточка: аватар/буква, имя, «Локальный профиль», «Сменить». Переключатель профилей — sheet со списком, добавить, переименовать, удалить. Создание и удаление профиля должны иметь явные формы; удаление требует подтверждения с именем и объёмом данных. Активный ответ при переключении: предложить дождаться/остановить; не передавать поток новому профилю.

Аватар: выбрать через photo picker, кадрировать, изменить, убрать. Имя: непустое, trim, рекомендуемый предел 80 символов (новая валидация), нормальная кириллица/emoji в имени. Пароль: задать/изменить/удалить, текущий пароль при изменении. «Пароль при запуске» и «Заблокировать» сохранить. Автоблокировка: выкл / 5 / 15 / 30 / 60 минут, плюс мобильная опция «При уходе в фон». При незаданном пароле соответствующие действия disabled с объяснением.

Биометрия — мобильная адаптация через платформенную службу, доступна только при настроенной защите и наличии ОС-возможности. UI-блокировка сама по себе не равна шифрованию чатов. Текст «только под учётной записью Windows» убрать. На этапе 1 не принимать настоящие секреты: показать demo-режим блокировки. Production keychain/keystore проверяется перед выпуском.

## 4. Модели — NavIcon.Models, фиолетовый

Исходные группы «Ответ в чате», «Агент», «Служебные». Сохранить: модель по умолчанию (мобильная явная строка), лёгкая, тяжёлая, маршрутизатор для «Авто», модель заголовков, модель сжатия/сводки. У каждой — провайдер/ключ, model picker и доступное reasoning. «Авто» только выбирает чат-модель; не запускает AgentHost и не выполняет инструменты.

В простом виде сначала «Модель по умолчанию». «Автоматический выбор» — отдельная раскрываемая группа с пояснением дополнительного запроса и его стоимости. «Названия и сжатие» — ещё одна группа. Можно отключить автоматические названия и использовать первые слова сообщения; пустая модель сжатия означает отсутствие этой возможности, а не тайный fallback.

Удалить AgentFast/AgentLite/AgentHeavy, FoxModel, персонажа, WebSearchField и выбор поискового движка инструментов. Не оставлять невидимые слоты в сериализованных мобильных настройках. Список реальных провайдеров определяется каталогом; исходник включает Venice/OpenRouter и прямые/совместимые endpoint. Не подменять исходные логотипы буквенными заглушками, кроме неизвестного кастомного сервера.

## 5. Промпты — NavIcon.Prompts, зелёный

«Основной промпт ИИ»: большой редактор, счётчик символов, сохранить, отменить, сбросить пользовательский текст после подтверждения. Библиотека ролей: список названий/начала текста, создать из редактора, открыть, применить, переименовать, удалить. Применение заменяет содержимое редактора с защитой несохранённого текста; отправка происходит только после сохранения/следующего сообщения.

Полностью удалить подпункт «Технические промпты», оба редактора TechAi/TechAgent, reset/save-кнопки и невидимую инъекцию этих текстов. В новом DTO нет соответствующих свойств. Не переносить системную инструкцию об инструментах из appsettings/констант под другим именем.

## 6. Инструкции — NavIcon.Instructions, бирюзовый

Исходный список: поиск по названию/триггерам/тексту, число элементов, создание, импорт .md, экспорт отдельной записи, включение. В телефоне поиск доступен внизу списка, «Создать» рядом/над ним. В карточке имя, preview, триггеры; no results и empty имеют разные тексты.

Редактор full-screen: «Включена», название, chips триггеров, поле добавления с кнопкой плюс (Enter/запятая также работают), Markdown-текст до исходного лимита 10 000 символов, счётчик, сохранить/отмена, меню экспорта/удаления. «Видна агенту» удалить. «Открыть папку» заменить экспортом через системный picker/share.

Критичное изменение поведения: в desktop модель вызывает read_instruction. В новом приложении инструмента нет. На первом этапе активные инструкции выбираются явно в настройках чата (все либо конкретные); UI показывает включённые. При дальнейшей интеграции текст выбранных инструкций добавляется напрямую в запрос с учётом контекста. Триггеры сохраняются как метаданные поиска/будущих подсказок; **не обещать прежнее семантическое автооткрытие**. Объяснение пользователю: «Выбранные инструкции используются в этом чате». Локальное сопоставление слов, если будет добавлено позже, не выдавать за прежнюю семантическую функцию.

## 7. Автоматизация — исходная молния, целиком исключена

Документируем, чтобы агент не пропустил раздел по ошибке. В исходнике 5 вкладок:

- **Рецепты**: список, название, инструмент, описание, аргументы JSON, значения по умолчанию; запустить/через агента/редактировать/удалить.
- **Расписание**: агентские проверки и результаты.
- **Отложенные**: напоминания, команды и отложенные запуски.
- **Компьютеры**: PowerShell Remoting и выбор целевой машины.
- **MCP**: внешние инструменты/серверы и их подключение.

Все отсутствуют в телефонном продукте этапа 1. Не переносить напоминания только ради заполнения страницы. Геометрия исходной молнии остаётся в reference-копии, но не включена в набор 10 экспортированных мобильных nav SVG.

## 8. Безопасность — NavIcon.Security, лиловый

Удалить режим доступа Normal/AskAll/ReadOnly/AlwaysApprove, SynGuard и его модель/reasoning, планы перед изменениями по трём уровням агента, список tools, включение всех tools, разрешённые домены загрузки агента. Эти параметры относятся к исполняемым действиям на ПК.

Сохранить приватность/шифрование чатов, но переопределить реализацию под mobile secure storage. На этапе UI строка объясняет demo-статус, не заявляет реально включённое шифрование. Production-операция должна иметь прогресс, отмену до commit и восстановление после сбоя. Блокировка экрана — в «Профиле», здесь ссылка туда без дублирования переключателя.

Мобильные адаптации: «Скрывать содержимое в переключателе приложений» (default on), управление разрешениями через страницу ОС, информация о локальном хранении и передаче отправленных сообщений выбранному провайдеру. Не обещать запрет скриншотов на всех ОС. Никакой аналитики или сбора содержимого чатов по умолчанию.

## 9. Ключи и траты — NavIcon.Keys, золотой

Исходный экран большой, на телефоне — одна страница с переходами в «Ключи», «История трат», «Лимиты». Верхние две карточки баланса сохраняются, но на 320 dp складываются вертикально. Подписи зависят от типа провайдера (USD/кредиты/токены), неизвестные данные — «—».

**Ключи.** Добавить; провайдер; URL собственного API при необходимости; masked key; необязательное название; ссылка «Где взять»; статус проверки; сохранить/отмена. Определение провайдера не должно молча перезаписывать явно выбранного. Пользовательский URL валидируется; проверка подключения не запускает платную модель. Строка ключа: имя, провайдер, маска, активный статус, доступная статистика. Показать/скрыть, переименовать, задать пакет токенов, передать другому локальному профилю, удалить/восстановить из короткой отмены. Нет чтения Windows environment variables. Для demo ключ — только синтетическая строка, без реальной проверки.

Во время хода credential snapshot неизменяем. Изменение/удаление задействованного ключа заблокировано с объяснением до завершения/остановки. Не выводить полный ключ в ошибке или telemetry. При переносе профиля секреты не включать в обычный экспорт.

**Траты.** «Все ключи» / «Один ключ», выбор ключа; День/Неделя/Месяц/3 месяца/Год/Всё время; сумма и кредиты; график; разбивка по моделям; обновить; экспорт CSV через share sheet. На телефоне график имеет доступное текстовое представление; периоды wrap/отдельный picker, не микроскопические 6 кнопок в ряд. Пусто/загрузка/ошибка/данные из кэша различаются. Отдельно пометить фактические цены и расчёт по usage.

**Лимиты.** Для профиля и отдельных ключей — день/месяц; на один ответ; процент предупреждения; низкий и критический остаток. Desktop-таблицы превратить в карточки «Профиль», «Ключ …» с вертикальными полями. Только неотрицательные числа, локальная запятая/точка принимается и нормализуется; пустое поле = нет лимита, не 0. Валюта явно указана. Порог предупреждения 1…100% (проектная валидация); критический остаток ≤ низкого. На этапе 2 лимит проверяется до запроса и обновляется после usage, а не гарантирует предел счёта у провайдера.

## 10. Данные — NavIcon.Data, серо-синий

- Чаты: разрешить sharing; импорт чата через file picker; экспорт из меню чата Markdown/HTML/PDF при наличии готового exporter. Для этапа 1 как минимум Markdown должен работать на demo-данных; остальные форматы показывают проверяемый preview/явную недоступность до реализации.
- Перенос данных: экспорт/импорт архива с выбором категорий и preview состава, конфликтами ID/имён, прогрессом и результатом. Исключить ключи, Windows-параметры, агента/Fox. Нельзя читать весь ZIP в память или доверять путям архива.
- Резервные копии: включить, ежедневно/еженедельно, сколько хранить, место через системный picker, последний результат, создать сейчас, восстановить выбранную копию. Мобильный background best-effort: не обещать точный ежедневный запуск. На этапе 1 ручная demo-копия; расписание показывает ограничения.
- Обслуживание: место по категориям/файлам, обновить; хранение старых чатов off/archive/delete, число дней; очистка кэша и неиспользуемых вложений; крупнейшие чаты. Автоудаление opt-in с подтверждением. Не удалять вложения, используемые другой ветвью/чатом.
- «Перезаписать вложения» старого формата — миграция, скрыть до обнаружения действительно старых данных; не добавлять бессмысленную кнопку на новой базе.
- «Файлы приложения» заменить страницей занимаемого места и действиями экспорта. Нельзя открыть произвольный desktop folder.
- Опасная зона: «Удалить все чаты» и «Удалить все данные профиля», разные диалоги с точным объёмом удаления и отдельным подтверждением. Остальные профили не затрагиваются.

Все настройки сохранения/очистки первого этапа применяются только к demo-store. В режиме preview это явно указано в разделе, чтобы тестовые кнопки не выглядели как доступ к реальным данным.

## 11. О программе — NavIcon.About, серый

Название Amarin Chat, реальная версия новой сборки, сведения о платформе; краткое руководство «ключ → модель → сообщение» с новыми мобильными экранами; документация/репозиторий; лицензии; сообщить об ошибке; просмотр/экспорт очищенной диагностики. Windows-скриншоты гайда — только справочные материалы разработчика.

Не переносить обновление EXE, rollback EXE, Windows-логи и installer. Для iOS — ссылка на выбранный канал распространения; Android update channel определяется способом доставки отдельно. На этапе 1 сведения о версии и release notes локальные; кнопка магазина не ведёт на выдуманную страницу. Beta-переключатель не показывать до реального beta-канала. ## Настройки конкретного чата

Меню названия чата или строки sidebar → «Настройки чата»: дополнительный пользовательский промпт, все/выбранные инструкции, сброс переопределений, сохранить/отмена. Источник `ChatSettingsOverlay.xaml`. Модель/effort меняются через composer, но хранятся для текущего чата. Приоритет промптов задать явно: глобальный пользовательский текст + дополнение чата + выбранные инструкции; не стирать глобальный промпт незаметно.

## Контроль полноты

Агент создаёт `implementation/settings-coverage.csv`: исходный Control Name / мобильный route / статус implemented, adapted, removed / причина / сценарий проверки. Начальная опись уже есть в inventory. Динамические строки (лимиты, меню ключа, очистка, темы) сверять по code-behind и каталогам, а не только XAML. Изменение смысла инструкции, голосового ввода и обновлений зафиксировано выше; никакую другую функцию не выкидывать молча.
