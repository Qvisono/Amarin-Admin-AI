# 06. Последовательность работ и приёмка

Не оценивать готовность количеством нарисованных экранов. Каждый этап заканчивается работающим маршрутом/состояниями и доказательством. Реальные сроки зависят от доступности устройств и mobile workloads; фиктивные оценки «всё за день» не нужны.

## P0 — проверить основу

Прочитать документы, сверить source-manifest, создать PROGRESS.md. Проверить SDK, Avalonia stable/templates, Android SDK/JDK/workload, device/emulator; записать фактические версии и отсутствующие компоненты. Для iOS зафиксировать доступ к Mac/Xcode/signing. Создать ADR выбора Avalonia.

Сделать один spike: native Android screen с многострочным вводом, русским текстом/IME, safe area, bottom sheet, свайпом, TalkBack; минимальный iOS host при доступной среде. Проверить keyboard resize, selection и Back. Если обнаружен блокер — воспроизводимый пример, вариант обхода, затем решение о MAUI. До успешного среза не писать десятки страниц на неподтверждённой основе.

Выход: фиксированные совместимые версии в global.json/Directory.Packages.props, сборка preview и Android; точный статус iOS. Никогда не менять исходную WPF-сборку ради mobile.

## P1 — дизайн-система и ресурсы

Перенести semantic colors всех 53 тем, mobile spacing/type/radii, шрифты и иконки по allowlist. Создать gallery состояний Button/Input/Switch/SettingRow/Sheet/ChatRow/Message/Composer. Сформировать icon-map.csv и atlas светлый/тёмный. Полнота сверяется с описями и code-generated иконками.

Выход: темы переключаются без потери экрана, кириллица читается, controls имеют pressed/disabled/focus/error, touch targets ≥44 dp iOS / ≥48 dp Android, никаких desktop glyph dependencies.

## P2 — shell, история и жесты

AppShell + stateful navigation, sidebar с нижним рядом «поиск + квадрат 1:1 справа» и строкой профиля, repository fake на 0/5/1000 чатов; папки/метки/архив; сортировка ASC и bottom alignment, поиск, long-press меню, мультивыбор. Back/focus/scrim. Реализовать gesture arbitration и взаимодействие с клавиатурой.

Выход: новые чаты внизу, старые подгружаются сверху без прыжка; нижние действия доступны после resize, поворота и поиска. Данные сортируются, визуальное дерево не переворачивается.

## P3 — чат и composer

Message list с Markdown, вложениями, цитатами, редактированием/ветвями; multiline composer и пять запрошенных групп управления. Модель/reasoning sheet, контекст sheet, баланс sheet. Fake stream: нормально, медленно, error после части текста, stop, offline, unknown balance. Native file picker для тестового документа/фото, с корректным cancel.

Выход: все сценарии воспроизводимы без API-ключа; draft изолирован по chat ID; typing и streaming не дёргают scroll; клавиатура не закрывает отправку.

## P4 — все сохраняемые настройки

Реализовать 10 разделов docs/03 и их редакторы. Switch/select сохраняются в demo-store; изменения темы видны сразу. Не делать заглушку из одной строки вместо сложного раздела. Заполнить settings-coverage.csv по исходной описи: каждая функциональная строка retained/adapted/removed с причиной и тестовым сценарием.

Особенно проверить: профили/автоблокировка, 53 темы, библиотека промптов, instructions без агентской семантики, custom endpoint форма, балансы unknown, график периодов, лимиты, import preview, очистка, guide/about. Крупный editor не должен терять текст при Back.

## P5 — убрать техническое наследие

Новый MobileSettings и ChatRequestBuilder. Структурные тесты DTO/payload: нет tools/tool_choice и запрещённых legacy источников; чистая история/ветви/инструкции работают. Проверить список ProjectReference/PackageReference/transitive dependencies. Не ограничиваться текстовым поиском «agent» в UI.

Выход: ни одна production-сборка не ссылается на WPF Core, Fox и Windows tools. Reference-папки не включены в runtime. Fake adapter не замаскирован под реальную сеть.

## P6 — мобильная проверка и исправления

Матрица ниже; screenshots всех основных страниц/пустых/ошибочных состояний. Локализованный текст и 200% font. Light/Dark/high contrast, жестовая и кнопочная системная навигация. Реальное устройство хотя бы Android, iOS отдельно. Не подменять это одним resize desktop окна.

На доступном среднепроизводительном устройстве измерить, а не угадать: длительность открытия sidebar/settings; прокрутку 1000 чатов и длинного ответа; память до/после 20 открытий sheet; время первого кадра. Проектные ориентиры: плавная прокрутка около 60 fps, реакция на tap без заметного зависания, sheet transition ≤220 ms. Записать устройство/режим/профилировщик; промахи объяснить и исправить. Не объявлять числа измеренными без замеров.

## Матрица экранов

| Режим | Что проверить |
|---|---|
| 320×568 dp | Полная панель ввода, поиск/footer, длинное имя модели, settings строки |
| 360×800 dp | Базовый Android, системный Back, клавиатура, file picker |
| 390×844 pt/dp | iPhone-компоновка, notch/home indicator, VoiceOver; подтверждение на iOS отдельно |
| 430×932 | Большой телефон, без ненужного растяжения текста |
| 800×360 landscape | Клавиатура, editor scroll, нижние действия, сокращение пустых зон |
| 600–840 и fold/unfold | Изменение размеров на лету, draft и scroll anchor сохраняются |
| Все ширины + 200% text | Нет обрезки обязательных значений и наложения кнопок |

Размеры — контрольные viewport, а не список гарантированно поддерживаемых моделей. Проверка эмулятора и реального телефона записывается отдельно.

## Финальный отчёт реализующего агента

Команды сборки и их результаты; APK и способ запуска; iOS build/run отдельно; таблица устройств; скриншоты; два coverage CSV; список известных дефектов и ограничений. Если Mac или Android tooling недоступны, работать над независимыми частями и честно помечать непроверенное. Нельзя назвать этап полностью принятым при невыполненных обязательных сценариях. Публикация и реальные API-платежи в этот этап не входят.

## Уточнения приёмки по концепту 02

- Стандартный однострочный composer ≈107/111 dp, text+toolbar; отдельной третьей строки метрик нет. Рост только по тексту/вложениям или large text.
- Поля поиска и кнопка нового чата одной высоты; кнопка строго квадратная и стоит справа.
- В sidebar нет дублирующего menu, крестика и стрелки. В настройках одна кнопка Back.
- В приложении нет нарисованных заменителей status bar/home indicator.
- Общий контрол контекста/баланса имеет один touch target и общий sheet; оба числа видны без открытия.
- Концепт проверен в браузере; эти результаты не закрывают native-сценарии Android/iOS.
