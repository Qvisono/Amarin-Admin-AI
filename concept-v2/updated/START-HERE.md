# Задание для Claude Code / Codex

Ты реализуешь отдельное мобильное приложение **Amarin Chat** в `D:\Amarin Microsoft\Amarin Chat S`. Исходное WPF-приложение находится в `D:\Amarin Microsoft\Amarin Admin AI`. Первый этап — полный качественный перенос применимого UI с адаптацией к Android/iPhone. Не ограничивайся одним экраном и не выдавай макет за готовое приложение.

Сначала прочитай README.md и все документы docs/01…08; **концепт 02 в docs/08 и design/mobile-concept.html — актуальный эталон**. Используй inventory/settings-source.md и CSV-описи для контроля полноты. Изучи references/screenshots/user и соответствующие файлы references/source. Источники стиля — оригинальные Amarin-ресурсы; Venice — референс мобильной компоновки. Не добавляй в продукт рекламу, Pro, Agentic Chat, персонажа или чужой логотип Venice.

Обязательные требования владельца:

- Sidebar открывается коротким свайпом вправо по чату и закрывается влево. Конфликты с кодом, выделением текста, системным Back и клавиатурой решены по docs/02.
- Поиск расположен снизу, квадратная кнопка нового чата 1:1 стоит справа от него в одной строке; отдельной широкой кнопки нет. Профиль и настройки — в самом низу. Чаты отсортированы по времени активности по возрастанию: самые новые ближе к нижним действиям. Не переворачивай визуальное дерево.
- Однострочный composer около 107/111 dp: текст и один toolbar, без отдельной третьей строки статистики. В панели ввода только текст, вложения, общая плашка модели с reasoning effort, контекст, остаток баланса и отправка/остановка. Никаких микрофонов, инструментов, режима агента, ПК, отдельной панели расходов или технических кнопок.
- Все применимые настройки, темы, меню, пользовательские промпты и инструкции переносятся. Судьба каждого исходного раздела описана в docs/03; исключённые разделы не оставлять пустыми вкладками.
- Субагенты, ProjectFox, Windows-инструменты, MCP/удалённые ПК, технические промпты и их невидимая подстановка полностью исключены из нового приложения. Исходное настольное приложение не изменять.
- Иконки сохраняют оригинальную геометрию. Никаких emoji вместо иконок и зависимости от Segoe MDL2 на телефоне.

Работай последовательно по docs/06. Начни с проверки среды и небольшого нативного прототипа Avalonia на Android: ввод кириллицы, клавиатура, safe area, свайп, доступность. Затем создавай shared UI + отдельные Android/iOS/desktop-preview проекты. Desktop-preview служит только быстрой проверке; он не доказывает работоспособность на телефоне. Фиксируй совместимые версии SDK/пакетов после успешного прототипа. MAUI — запасной вариант только при воспроизводимом блокере Avalonia; аргументируй смену в ADR.

На этом этапе нужны реальные навигация, формы, изменения настроек в локальном демонстрационном хранилище, работа с черновиками и состояния экрана. Для ответа модели, баланса, каталогов и сетевых ошибок используй управляемые fake-сервисы, явно обозначенные как demo в сборке. Не отправляй платные запросы. Подключение реальных провайдеров — отдельный следующий этап, но контракты должны быть готовы.

Не используй ProjectReference на старый Amarin.Core: он net10.0-windows и содержит зависимости PowerShell/WMI/DPAPI. Не переносить весь ChatEngine и AppSettings. Собери небольшое переносимое ядро и интерфейсы платформенных служб. Не путай отсутствие инструментов в UI с их отсутствием в API-запросе: проверка должна охватывать сериализованный payload и зависимости приложения.

Добавь `PROGRESS.md`: выполненные задачи, команды и результаты проверок, реальные устройства/эмуляторы, скриншоты, блокеры. Для iOS требуется доступная macOS/Xcode-среда: если её нет, продолжай Android и shared UI, но пометь iOS как непроверенный, не объявляй этап полностью принятым. Не устанавливай крупные workloads скрытно; сначала перечисли отсутствующие компоненты и выполни доступные задачи.

Конечный результат этапа: исходники нового проекта, воспроизводимая debug-сборка Android, iOS-проект и честный статус его проверки, все сохраняемые страницы настроек, тестовые сценарии, карта переноса иконок, скриншоты размеров 320/360/390/430 dp и landscape, выполненные критерии docs/06. Дай короткий отчёт о том, что реально проверено и что осталось. Начинай реализацию, а не повторное составление общего плана.
