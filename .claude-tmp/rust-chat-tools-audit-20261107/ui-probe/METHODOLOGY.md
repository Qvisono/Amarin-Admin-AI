# Что именно измеряет UI probe

Это базовые времена существующей Release-сборки C# на синтетике. Rust не реализовывался и не
измерялся. Ни скорость запуска всего приложения, ни время открытия чата этим probe не измеряются.

## Изоляция

- В отдельном STA-процессе создаются `Application`, `Grid` и один `RichTextBox`.
- `Window`, `MainWindow`, `Show`, `Application.Run`, `UiServices`, `AppComposition`, профиль и
  хранилища не создаются. `ThemeManager.Initialize`/`LanguageManager.Initialize` не вызываются.
- Загружаются только встроенные BAML-ресурсы `Palette.Dark`, `Icons.Dark`, `UI/Resources`.
- Нет URL, изображений, пользовательских вложений, кликов, буфера обмена, сети или tools.
- JSON и превью PNG пишутся в папку probe, `TEMP`/`TMP` задаются внутри неё.
- Нулевое число окон записывается в JSON. Превью 20k rich/code первого прогона визуально проверены:
  действительно видны текст, списки, жирное/курсивное выделение и цветной C#.

## Фазы

1. `parse_only`: `ChatMarkdown.Parse(text)`, включая нормализацию и Markdig, без WPF-документа.
2. `highlight_uncached`: только `CodeHighlighter.Highlight` без кэша, для C# кода отдельно.
3. `highlight_cached_hit`: тот же код уже присутствует в кэше; не отражает меняющийся текст.
   В коротком повторе дополнительно отдельно измеряется приватный `CodeBlockView.MeasureWidest`
   (через один заранее созданный delegate): построчный `FormattedText` без кэша и с кэш-попаданием.
   Reflection discovery/delegate creation не входят в замер.
4. `build_from_parsed_*`: `ChatMarkdown.Write` с уже разобранным деревом Markdig и существующим
   RichTextBox. Включает новые WPF-объекты, динамические ресурсы, вложенные блоки кода, их
   подсветку и `CodeBlockView.MeasureWidest` через построчный `FormattedText`.
   Поэтому название build не означает чистую CPU-сборку дерева без шрифтовых измерений.
5. `layout_after_build_*`: новый документ строится перед таймером; внутри таймера только
   `Measure` + `Arrange` + `UpdateLayout`.
6. `build_and_layout_*`: обе фазы в одном измерении, без повторного Markdig parse.
7. `render_visible_900px_after_layout`: `RenderTargetBitmap.Render` стабильного документа после
   раскладки в bitmap 760x900 при 96 DPI. Это offscreen raster preview, не время monitor frame,
   не частота кадров и не настоящий compositor/PresentationSource.

`streaming=true` повторяет текущий путь приложения без кэша подсветки и замеров ширины блоков.
`finished_cached` повторяет неизменный текст с уже заполненными кэшами. Между разными фазами
нельзя трактовать разность медиан как точный causal speedup: порядок фиксирован, работают
внутренние кэши WPF/.NET, GC и частотное управление процессора.

## Геометрия и шрифты

Ширина 760 DIP. `RichTextBox` не имеет scrollbars и фиксированной высоты; как тело сообщения,
он измеряется с бесконечной высотой и располагается с полученной полной высотой. Поэтому
измеряется раскладка всего одного документа, даже когда PNG захватывает только первые 900px.
Это не 900px-виртуализация документа. Время не включает построение множества сообщений,
список чатов, services, изображения, сеть, обновление/переиспользование message hosts.

Текст использует Segoe UI 13.5 DIP, код - текущий заводской `ChatFonts.Mono`/`MonoTypeface` из
сборки, без чтения пользовательских настроек. Ресурсы и шрифты прогреты. В первом прогоне
runtime tiered JIT оставлен по умолчанию; для короткого повтора он выключен переменной
`DOTNET_TieredCompilation=0` только в дочернем процессе.

## Нагрузка и ограничения

`rich_markdown`: повтор короткого заголовка, абзаца со стилями и списка. 20k символов дают 595
верхнеуровневых блоков, 100k - 2971. Это намеренно плотный stress case, а не обычный чат.

`csharp_block`: заголовок и один fenced code block. Код состоит из строк длиной 55 символов:
20k символов кода - 364 строки, 100k - 1819 строк. Это отдельный stress длинного блока кода.

`plain_prose`: обычные длинные абзацы без Markdown-стилей, чтобы не переносить результаты
плотного stress case на типичный текст.

Allocations измерены через `GC.GetAllocatedBytesForCurrentThread`. Это байты управляемых
выделений STA-потока за операцию, а не retained memory, рабочий набор, пик RAM или объём native
WPF/GDI/GPU. Одна разогревающая операция, затем 5 измеренных; записаны все samples, медиана,
минимум/максимум и GC counts. Измерения исследовательские и не заменяют профиль production.
