# UI baseline: C# Release, синтетический offscreen WPF

Краткий повтор: `ui-results-run2.json`. Одна разогревающая операция и 5 измеренных, медианы.
`DOTNET_TieredCompilation=0`, отдельный процесс, параллельные сборки/замеры не запускались.
Ни одно видимое окно не создавалось, `Application.Windows.Count=0`.

| Сценарий | Parse, ms | Build из parsed tree, ms | Layout отдельно, ms | Build+layout, ms | Managed allocations build+layout, MB |
|---|---:|---:|---:|---:|---:|
| Обычный текст, 20 000 символов, 28 абзацев | 0.083 | 4.412 | 62.128 | 64.417 | 3.836 |
| Плотный Markdown, 20 000 символов, 595 блоков | 0.882 | 231.242 | 581.565 | 876.264 | 41.020 |
| Один C# блок, 20 000 символов кода, 364 строки | 0.140 | 490.109 | 113.439 | 495.199 | 50.471 |

Все строки используют `streaming=true`. Parse и build/layout измеряются отдельными сериями,
их медианы не обязаны складываться. Build уже включает подсветку и построчные замеры кода.
В фиксированном порядке серий работают WPF/.NET кэши, GC и частотное управление процессора;
не следует считать разность отдельных медиан точной долей времени конкретного подметода.

Снимки RenderTargetBitmap непустые: rich 33 665, code 645 665, plain 115 514 неблэк-пикселей.
Rich/code PNG визуально проверены: видны корректный текст, списки, выделения и цветная подсветка.
Ширина 760 DIP, PNG захватывает первые 900px после полной auto-height раскладки документа.

Что подтверждено: на этой синтетике стоимость полного пересоздания и раскладки WPF-документа
существенно выше чистого Markdown-парсинга и подсветки. Перевод только Markdig/ColorCode
в Rust не уберёт основную наблюдаемую работу WPF. Перспективнее проверить переиспользование
завершённых блоков и инкрементальное обновление хвоста ответа.

Что не подтверждено: коэффициент ускорения от Rust, время настоящего OpenChat, холодный запуск
приложения, расход RAM/native памяти, FPS рабочего окна или типичные задержки у пользователя.
595 блоков в 20k Markdown и 364 строки кода - отдельные stress cases, не типичный короткий ответ.

Первый исследовательский прогон `ui-results-run1.json` дополнительно содержит 2k/20k/100k
сценарии с runtime tiered JIT по умолчанию. Ранняя часть могла пересечься с независимой сборкой,
поэтому не используется как сравнение с повтором. В том прогоне 100k плотного Markdown
(2971 блок) занимал около 2474ms build+layout и 201.7MB managed allocations; это исключительно
stress baseline, не измерение старта и не результат Rust-переноса.

Полная безопасность и определения фаз: `METHODOLOGY.md`. Production-код и штатные тесты
не изменялись. Временный probe собран Release без предупреждений; оба измерительных прогона
завершились с кодом 0.
