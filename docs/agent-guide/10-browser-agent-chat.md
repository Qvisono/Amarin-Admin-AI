## Агент и чат (1.37.0, раздел B)

**Браузер агента — WebView2 в своём окне, управление через DOM.** Пакет `Microsoft.Web.WebView2`
только в приложении; ядро говорит с ним портом `IWebBrowser` (`Amarin.Core/Browser`), как с мышью.
Фабрику окна ставит главное окно (`MainWindow.AgentBrowser.cs`, только `IsRealApp`), без неё
`BrowserHub.Open` отдаёт null и агент инструмента `browser` не получает. Сеанс — на прогон агента
(`AgentHost.RunCoreAsync`), окно открывается первым действием и закрывается с концом прогона;
браузер один на процесс (свой `ComputerLease`). Профиль — `browser/` в папке профиля: в архив не
едет, «Удалить все данные» его стирает, куки и пароли и так закрыты правилом `SensitivePaths` по
имени файла. Страница читается скриптом с метками `data-amarin-id` вида `b<чтение>_<n>`: новое
чтение снимает прежние, и устаревший id — отказ «прочитай заново». Нажатия и ввод — доверенными
событиями DevTools (`Input.dispatchMouseEvent`, `Input.insertText`): синтетический `click()` часть
сайтов не принимает. Шлюз — как у мыши (`ToolGate.IsHands`): запись без вопроса в обычном режиме,
SynGuard судит записи и видит страницу (`Agent.GuardPage`), чтения не судит; адрес `open` режет
`BrowserSafety` в `HardBlock` (только интернет: не файлы, не этот ПК и не локальная сеть), и тем же
правилом окно режет переходы, начатые страницей. Пароль агент не вводит — `handoff` показывает
человеку полосу с «Готово» (без человека — отказ) и ждёт в том же прогоне: окно закрывается с концом
работы, и агент, написавший «войдите сами», оставлял человека без окна. Поэтому с 1.37.1 агент, который
заканчивает, оставив окно на странице с полем пароля, раз за прогон получает напоминание
(`Agent.BeforeFinish` ← `BrowserSession.SignInLeftOpen`), а закрытое человеком окно отвечает ожиданию
сразу, а не через десять минут. Загрузки страницы — через белый список и
`DownloadAccessBroker`, как у `download_file`. Окно картинок (`ComputerHistory.Trim`) оставляет
модели последнее чтение страницы. Живой прогон — `AgentBrowserLiveTests` (`AMARIN_BROWSER_LIVE=1`).

**Какой инструмент для сети — решает правило, а не привычка (1.37.0-beta.8).** `BrowserPrompt.AgentRule`
делит по тому, что нужно сделать: узнать — `search_web`, прочитать известную страницу — `scrape_url`,
действовать на сайте (вход, формы, кнопки, страница только для браузера) — свой браузер, окна
программ — `computer`, показать страницу человеку — `Start-Process` в его браузере (окно агента
закрывается с концом прогона). Правило перекрывает и базовый промпт, и правило мыши об открытии
сайтов. Браузер выключен — агенту `AgentOffRule` (только когда хаб есть и цель — этот ПК), чату
`ChatOffRules(mouse)`: оба называют переключатель в «Безопасности», а не обещают браузер. Сбой
движка — ответ модели (`BrowserTool`, `BrowserSession.TryPort`, любая ошибка запуска в
`WebViewBrowser.EnsureAsync` закрывает окно): до этого всё, кроме двух типов исключений, роняло весь
прогон агента.

**Прежние страницы агент помнит кратко, а не теряет (1.37.0-beta.8).** `ComputerHistory.Trim` раньше
заменял каждое прежнее чтение страницы заглушкой целиком, и у агента оставалась одна страница: открыв
пункт списка, он забывал список, вернувшись — пункт, и ходил между ними десятками раундов. Теперь
последнее чтение — целиком, прежние `KeepPageDigests` разных адресов — кратко (`BrowserTool.Digest`:
заголовок, адрес, текст и ссылки без id — адреса пунктов часто есть только у элементов), прежнее
чтение адреса, прочитанного позже снова, и всё старше — адрес и заглушка. Страницы, которых модель
ещё не видела (ответы на её последний ход), остаются целиком все: модель открывает по нескольку
страниц за ход, и обрезанные до того, как она их прочла, она открывала снова той же пачкой без конца.
Формат выдачи страницы и его разбор живут в одном `BrowserTool`. С `RepeatedVisit`-го открытия того
же адреса ответ напоминает, что страница уже в истории; правило агенту — записывать нужное, прежде
чем уйти со страницы. `read` с адресом другой страницы открывает её (и шлюз проверяет адрес, как у
`open`): прежде адрес молча пропускался. На настоящем чате с 91 чтением дюжины адресов история
страниц — 26 тысяч знаков вместо 264 тысяч целиком.

**Выдача ложится на свой вызов и после пересадки (1.37.0-beta.8).** `AgentUiAdapter.ToolResult`
находит вызов по имени — первый незавершённый; вызов, оборванный пересадкой, оставался «выполняется»,
и в ленте каждая выдача новой попытки стояла под вызовом раньше. Новый адаптер той же записи
закрывает такие вызовы «отменено» (`SettleInterrupted`). Просьба «быстрее» агенту, который уже на
этом уровне, — вводная (`Tell`), а не пересадка: та же модель начинала задачу с нуля.

**Пересадка работающего агента сохраняет найденное (1.38.0).** Отмена попытки теперь оставляет
снимок `Agent.SessionHistory`: его принимает `AgentHost` и продолжает через `ResumeAsync`, а не
начинает исходное задание заново. Реплика `message_agent` уже в снимке, второй раз добавлять её
нельзя, но она остаётся в задании SynGuard. Прочитанные уточнения человека (`HumanNotes`) тоже
переезжают: одна непрочитанная очередь `carried` их не содержит. История при пересадке не проходит
`SessionHistoryCompressor`, иначе старое начало запроса меняется и часть результатов теряется.
Незавершённые tool calls закрываются ответом с неизвестным исходом и советом проверить состояние
перед повтором: отменённая запись могла успеть что-то изменить. Параллельный раунд дожидается
`WhenAll` и в `finally` добавляет готовые результаты соседей, даже если другой вызов отменён.
`ReplayBlocks` с подписью Anthropic сохраняются только при той же модели; при смене модели
`ChatMessageCloner` убирает их из переносимой копии. Id агента и cache key прежние, но готовый кэш
одной модели не переносится в другую. Регрессии - `AgentSwitchHistoryTests`, настоящий хост с
подставными HTTP-ответами и инструментами.

**Элементы страницы — как их видит человек (1.37.0-beta.8).** Скрипт чтения (`WebViewBrowser.Describe`)
называет поле и переключатель подписью (`aria-labelledby`, `label`); атрибут `name` — последний запас:
он служебный и у группы переключателей один, и варианты теста приходили модели пятью одинаковыми
«q…:20_answer». Спрятанное от человека в список не идёт: `aria-hidden`, `inert`, обрезанное до точки
(`clipped`, приём `sr-only`). У Moodle в каждом вопросе такой переключатель «Очистить мой выбор»,
отмеченный, пока ответа нет: агент нажал его вместо варианта, читал «checked» и до конца попытки думал,
что ответил, а «Закончить попытку» отправляла пустой ответ. Флажок, нарисованный своей подписью (сам
спрятан или обрезан), остаётся в списке и нажимается подписью (`stand`). Проверяет только живой прогон
(`AgentBrowserLiveTests`, разметка вопроса Moodle страницей `data:`). Правило агенту: выбор на странице
хранится, только когда её отправляет своя кнопка (открыть адрес или назад — потерять), а шаг, дважды не
сработавший, тем же способом не повторяется — снимок, другой путь или остальная работа без него.

**Значок под ответом размером в 14 точек.** Значки ряда — `DrawingImage` в `Icons.Dark/Light`, и
картинка растягивается по самой фигуре: у обводки без заливки рамка — это сама обводка, а не бокс
24. Поэтому размер задаёт поле кнопки в `ChatMessageViews.IconAction`: обводке (скобки выгрузки,
ветка, корзина) — 6, иначе она выходит на 18 точек при 13-15 у соседей; толщина обводки
подбирается так, чтобы значок не был светлее соседей.

**Приватность — подстраница «Безопасности» (`PrivacySub`):** шифрование чатов, провайдеры без
хранения данных и срок временного чата. Временный чат включает кнопка-инкогнито в строке заголовка
(`TemporaryChatButton`, только у пустого чата; включённая зачёркивается), а посреди пустого
временного чата — рисунок инкогнито с названием и строкой пояснения (`TemporaryChatEmpty`); у
обычного пустого чата середина пуста (1.37.0-beta.7, концепт выбрал человек).

**Временный чат не пишет хранилище.** Признак `ChatSession.IsTemporary` (`[JsonIgnore]`), охрана —
в `ChatStore.Save`: ни файла, ни описи, ни события `Saved` (значит, ни поиска, ни архива, ни копий).
Список временных — `TemporaryChats` у окна (`MainWindow.Temporary.cs`); в режиме «до закрытия»
(`AppSettings.TemporaryChatsUntilClose`) они стоят своей группой наверху списка, в режиме «сразу»
уход из чата его удаляет (`LeaveTemporary` в `StartNewSession`/`LoadSession`). Черновик временного —
только в памяти (`DraftKey` — свой id, без записи), сводка не считается, Розе текст не уходит,
`deferred_task` отказывает (`AgentRunContext.TemporaryChat`). Журнал аудита и траты пишутся как обычно.

**Ветка в новый чат — `ChatBranchCopy`, не `ChatBranches.Fork`.** Копия через JSON хранилища до
ответа включительно (`ChatSessionEdit.ApiCut`), без спрятанных вариантов, цен, отметок отложенных
задач и разговоров с агентами; сжатие сбрасывается, если граница позже обреза. Кнопка — только у
ответов модели, значок `Branch` в обеих темах значков.

**Разговор с агентом живёт по настройке (`AppSettings.AgentMemory`).** `AgentMemoryBook` (корень
композиции) отдаёт ходу `VeniceTurnContext.Agents`: новый на ответ, общий на чат в памяти или поднятый
из `ChatSession.Agents` (режим «сохранять в чате», без ограничения числа сохранённых разговоров).
Одновременно работают не больше четырёх агентов через `AgentSlotLimiter`. Номер нового агента —
`AgentConversations.Allocate`: счётчик реестра на каждом запуске идёт с a1, а агенты из файла помнят
свои номера; `AgentRegistry` хранит работающих по паре «чат + id». Срок жизни модели называет блок
`ChatEngine.AgentLifetimeRules` в системном промпте, а не описание `message_agent`.

**Скорость модели — `ReasoningChoice.Speed`, таблица — `ModelSpeeds`.** Каталоги уровней не
сообщают, поэтому таблица по провайдеру и семейству; на провод уходит только то, что модель умеет
(`service_tier` у OpenAI и OpenRouter, быстрый — старым именем `priority`; `speed: "fast"` с бетой у
официального API Anthropic), а 400 о поле снимает его повтором. Оценка цены прямых провайдеров
умножается на уровень, каким ответ обслужили (`service_tier` ответа, `usage.speed` у Anthropic).

**Приватность OpenRouter и белый список.** `AppSettings.OpenRouterNoRetention` уходит в каждый запрос
к OpenRouter полем `provider` через делегат `AgentOptions.NoRetention`; пакетные модели при нём идут
мимо очереди (она хранит заявки до 30 дней), Decisions получают тот же фильтр. «Загрузка с любого
сайта» (`AppSettings.DownloadAnySite`) — статика `DownloadValidator.AllowAnySite`, её ставят запуск,
переключатель и смена профиля (`AppServices.UseProfile`). Обе — настройки защиты: в существующий
профиль из архива не приезжают; браузер агента и загрузка с любого сайта сбрасываются и у нового.

**Размер загрузки настраивается в профиле (1.38.0-beta.2, раздел B).**
`DownloadSizeLimitEnabled` снимает общий предел, не стирая `DownloadMaxSizeMb`; null у числа
наследует прежний `DownloadOptions.MaxSizeBytes` из конфигурации. `WebDownloadTool` читает
настройки делегатом на каждый вызов; его передают и агенту, и ленивому набору рецептов, чтобы
не оставался предел старого профиля. Положительный `max_size_mb` отдельного вызова только
уменьшает предел. Проверяются заголовок и фактические байты; недокачанный файл удаляется.
Внутренний `DownloadAsync` принимает уже проверенный путь для потоковых тестов во временной
папке; публичный вход не обходит URL, белый список и `DownloadPaths`. Оба новых поля едут
с `settings.json` обычным экспортом/импортом.
